# Plan — Order Number, Promo Persistence, Email Discount Breakdown

Supersedes the original 3-phase plan (Auth & Session Fixes, Checkout Flow Overhaul, UI/UX Revamp — all completed and committed). Phases run in order — each phase's UNTIL must be true before starting the next.

Admin role assignment is handled directly in the database by the owner — no seed/bootstrap script for it in this plan.

---

## Phase A — Scalable Order Number (`TVA<seq>`)

GOAL: Every order gets a short display number in the form `TVA<sequence>` (e.g. `TVA100001`), generated by a real Postgres sequence. The UUID (`orders.id`) stays the primary key/FK target and stays in every URL — it is never shown to a human. Every human-facing surface (customer UI, email, admin portal) shows only the `TVA<seq>` number.

UNTIL: A newly created order gets a real `TVA<seq>` number from the DB sequence; it displays correctly on the confirmation page, account order-history list, order status page, admin table (list + ship dialog + toast), and the confirmation email; existing test orders got sane backfilled numbers; the Cashfree order note shows the same number.

## Phase B — Promo Code Persistence (Cart → Checkout), URL-driven for future ad links

GOAL: A promo applied on the cart page is still applied at checkout — no re-entry required — and a promo code carried in the URL (e.g. `/products?promo=WELCOME10`, for future ad campaigns) auto-applies and then persists the same way. Global promo state lives in a `zustand` store; `nuqs` handles the `?promo=` URL param.

UNTIL: Apply a promo on `/cart`, go to `/checkout` — it's still applied with the same discount, no re-entry. Visiting any storefront page with `?promo=<valid-code>` auto-applies it, and it's still applied at checkout. Completing the order clears cart + promo together. Removing the promo anywhere clears it everywhere.
